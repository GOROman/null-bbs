# 設計メモ

## 全体の構成

```
main ─┬─ tokio ランタイム
      │   ├─ TCP の待ち受け ──(接続ごと)── 読み書きのタスク ─┐
      │   ├─ モデム回線のタスク × 回線数                     │
      │   │     ↑↓ チャネル                                  │
      │   │   シリアルの読み込み / 書き込みスレッド          │
      │   └─ セッションのタスク (1 回線に 1 つ) ←────────────┘
      ├─ DB スレッド (SQLite の接続を 1 つだけ持つ)
      └─ 管理コンソールのスレッド
```

- **回線の共通化**: TCP もモデムも、チャネルの組 `Conn` (`src/line/mod.rs`) としてセッションに渡します。セッションのコードは、どの回線から来たかを気にしません。
- **セッション**: 状態機械にはせず、async 関数で上から下へ素直に書いています (`src/session/`)。`read_line().await?` の `?` で、切断やタイムアウトがどの深さからでも伝わります。
- **割り込み表示**: `Term::read_line` (`src/term/mod.rs`) は、入力・通知 (全体放送 / 電報 / チャット / 強制切断)・無操作タイマー・接続時間の上限を同時に待ちます。通知が来たら表示して、プロンプトと打ちかけの文字を出し直します。
- **共有状態**: `Hub` (`src/hub.rs`) が、回線ごとの状態、通知の受け口、チャットの部屋を持ちます。通知の受け口は大きさが決まっていて、あふれた通知は捨てます。遅い回線に全体が引きずられないようにするためです。
- **DB**: rusqlite の接続を専用スレッドに 1 つだけ持たせ、クロージャを送って実行します (`src/db/mod.rs`)。マイグレーションは `PRAGMA user_version` で管理します (`migrations/`)。
- **シリアル**: `serialport` のブロッキング API を、読み込みと書き込みの 2 本のスレッドで扱います (`src/line/serial.rs`)。書き込みはタイムアウトしても待ち続け、遅い回線でも取りこぼしません。

## I/O を持たない部品

次の 3 つは入出力から切り離してあるので、単体でテストできます。

| 部品 | ファイル | 内容 |
|---|---|---|
| `Telnet` | `src/line/telnet.rs` | IAC の除去とネゴシエーション (ECHO / SGA / BINARY)、改行の正規化 |
| `Editor` | `src/term/editor.rs` | UTF-8 の 1 行入力。分割されたマルチバイト文字、全角の BS、エスケープシーケンスの読み飛ばし |
| `Transfer` | `src/transfer.rs` | XMODEM / XMODEM-1K / YMODEM の送受信 (null-term と共通) |

## ファイル転送と telnet

telnet では 0xFF (IAC) を 2 つ重ねて送り、CR の後ろの NUL や LF は捨てます。
ファイル転送中は、`LineInfo::binary` を立てて改行の処理を止めます。こうしないと、バイナリのデータが壊れます。
